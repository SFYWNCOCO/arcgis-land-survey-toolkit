## 三、工序五步：收 → 套 → 填 → 校 → 交

### 第1步 收：收件与登记

- 输入：自然资源部门移交的 `项目编号.gdb`（附录H 第58页）：`补充耕地国土变更图斑`（DLTB）+ `补充耕地质量鉴定图斑`，及附件材料。
- 动作：只读打开，登记图层名、要素数、坐标系、字段清单、移交人/日期；原件保持不动，必要时先做只读副本再操作。
- 产物：《收件清单》（图层、要素数、WKID、字段、移交信息）。
- 判据：目录层级与附录H 一致；两个面图层都在；坐标系可识别（CGCS2000 3度带，示例区源数据为 EPSG:4524 = CGCS2000 / 3-degree Gauss-Kruger zone 36）；缺件即停，不得自行生成 DLTB，也不得拿项目地块 shp 冒充鉴定图斑层。

### 第2步 套：套合与 DK↔BSM 对照

- 输入：移交的鉴定图斑层、项目地块矢量（示例区为单层 shp）、项目资料。
- 动作：空间相交/叠加，建立"鉴定图斑 BSM ↔ 项目地块 DKBH"对照；一对多、无匹配、跨地块、面积差异常逐条列出。
- 产物：《图斑-地块对照表》（BSM、DKBH、图斑面积、重叠面积、匹配方式）。
- 判据：每个项目地块至少对应 1 个鉴定图斑；每个鉴定图斑归属唯一地块；不能唯一归属的标 NEEDS_REVIEW，不得硬拆或硬并。

### 第3步 填：按来源赋值

- 输入：对照表、变更调查数据、项目资料、人工确认的取值文件（attrs-json）。
- 动作：按字段来源分组赋值，同批写字段状态；无来源字段留 NULL 并进《待补清单》，禁止用"待填/未知/无/××"之类占位文本冒充取值。
- 产物：附录C 图层草稿 +《字段来源表》+《待补清单》。
- 判据：29 字段齐全；每个非空值可追溯到来源或推导规则；ASSUMED 值必须带确认人/依据。

**面积口径（注2 要重算的三个面积，最容易错）**：

- TBMJ 图斑面积 = **毛面积**：图斑边界内合计，含扣除地类。
- KCMJ 扣除地类面积 = 图斑内扣除地类部分；源几何带内环（孔洞）时，孔洞即扣除地类，KCMJ 取孔洞合计。
- TBDLMJ 图斑地类面积 = **净面积** = TBMJ − KCMJ；孔洞情形下等于几何净面积。
- 禁止把 TBMJ 直接取几何净面积；TBMJ 与 TBDLMJ 同值即口径矛盾，必须回查（示例区教训见第五节第6条）。
- 只有存在孔洞才填 KCMJ；KCDLBM、KCXS 推不出具体扣除地类码时不填、留待补，KCXS 值域〔0,1)，不得硬填 1 顶替。

字段来源分组（与 references/04 第二节末句一致）：

|---|---|---|

| 12、15、16 | 由图形/扣除关系重算，不能用调查库原值顶替 | 注2 |

### 第4步 校：结构、值域与几何

- 输入：草稿图层、检查脚本/报告。
- 动作：按下列 6 组逐项检查，结果只记 PASS/FAIL/NEEDS_REVIEW/UNVERIFIED。
  1. 结构：29 字段、字段名、类型、长度（Char30/254/3、Double 15,2、KCXS Float 6,4）与 references/04 表一致；GXSJ 表内写 Data 8（PDF 原文印作 Data，应为 Date 之误印），ArcGIS 建库按 DATE 落库，`qa.py` 的 `APPENDIX_C` 用 Date 属映射口径，两者不矛盾。
  2. 值域：SFYKT/SFFK/SFZPJ ∈ {是, 否}；BCFS ∈ {Z, G, J, K, Q, F}；BCGDLY ∈ {恢复, 垦造}；KCXS ∈ 〔0,1)。
  3. 标识码：BSM 非空、不重复；不唯一时按 −1、−2、−3… 后缀且序列连续。
  4. 面积：TBMJ 取毛面积（含扣除地类）、KCMJ 取图斑内扣除地类（孔洞即孔洞合计）、TBDLMJ = TBMJ − KCMJ；不得拿几何净面积当 TBMJ，TBMJ = TBDLMJ 必须按口径矛盾复核；JZGDMJ > 0；重算过程留档。
  5. 几何：以 `partCount > 1` 判真多部件（计数必须为 0）；`isMultipart` 对"单部件带孔洞"也返回 True，不能作判据（此前误报已确认，工具侧改按 partCount）；带孔洞的单部件不属注6 禁止情形，但孔洞与细缝连接仍要影像人工核查（规范未给宽度阈值，本页不设数字）。
  6. 坐标与格式：CGCS2000、1985 国家高程基准、高斯-克吕格投影 3 度分带；§5.3 的资料收集格式为 shp 矢量 + TIFF 栅格，成果汇交按附录H/附录I 用 .gdb，两者用途不同，不要混用。
- 产物：《检查报告》（每项状态 + 证据 + 需人工确认项）。
- 判据：FAIL 必须修复后重跑；NEEDS_REVIEW 必须人工确认并留依据；UNVERIFIED 不得当作通过；PASS 只代表该条自动规则通过。

### 第5步 交：落成果目录

- 输入：通过检查的图层、检查报告、待补清单。
- 动作：写入附录I 成果库 `数据库成果/项目编号.gdb`，与 DLTB、耕地质量等级评价评价单元图并列；报告与清单随成果留存；输出目录已存在时拒绝覆盖。
- 产物：符合附录I 的目录树 + 报告 + 清单。
- 判据：目录层级与附录I 第59页（印刷页53）一致；鉴定图斑层保持移交原样（附录I 注2）；文件名、项目编号、单元编号、样品编号四处交叉一致；空目录或占位文件不算齐全。
- **例外（示例区即此情形）**：附录I 注2 要求鉴定图斑"由自然资源部门移交、不做任何修改"。若自然资源部门只提供项目地块 shp、没有移交 DLTB 与鉴定图斑层，农业农村部门只能按附录C 建**底稿**，成果与报告须标注"非移交原件、待自然资源确认"，不得当作已移交；一旦拿到移交原件，以原件替换，不再重算、改字段或重编号。

## 五、示例区实战结论与缺口（2026-11-03 实测）

源数据事实：唯一可用矢量 `D:\work\高标准\示例区2025年度第一批耕地恢复.shp`，9 个面要素（其中 22、111、1 号带内环/孔洞），EPSG:4524；字段 PL_NAME、DIKUAI_NO、DIKUAIAREA、MAP_NO、PATCHTYPE、AVGGRADE1、AVGGRADE2、LANDTYPE（旱地）、PURPOSE（开垦）、BZ、XMBH（F99000120260000）。

11 个必填字段无直接来源：BSM、XZDM、XZMC、BGQDLBM、BGQDLMC、ZLDWDM、ZLDWMC、GXSJ、SFYKT、SFFK、BCFS；其中 BCFS 可按 15 位编号规则由 XMBH 首字符推导为 DERIVED（本例 F→非项目类），其余 10 项为 MISSING。条件必填中，KCMJ 已由孔洞推导：22=441.77 m²、111=837.49 m²、1=539.40 m²（两块孔洞 305.211+234.164=539.375，ArcGIS 读回 539.40 m²），6 块无孔洞为 0，产出层孔洞合计 1818.66 m²（源环面积累加 1818.63 m²，差异来自几何面积算法取整）；KCDLBM、KCXS 因推不出扣除地类码与系数仍 MISSING；GDLX、GDPDJB 无权威码表，也为 MISSING。

结论：

1. **源 shp 不能单独成附录C 图斑**：缺的 11 个必填项里，BSM、乡镇/坐落单位、变更前地类、更新时间、是/否判定只能来自自然资源部门移交的 DLTB/鉴定图斑和项目资料；补充方式可由项目编号首字符推导，但须与系统备案号核对。
2. 正确路径是先"收"到移交 gdb 的鉴定图斑，再用"套"把项目地块挂到 BSM 上，缺的字段按来源补，而不是从项目地块反向造图斑。
3. 无来源字段一律 NULL + 进《待补清单》，禁止自造；项目地块字段只能作为线索（如 DIKUAI_NO 疑似对应 DKBH、XMBH 疑似对应项目编号、BZ 可转备注、LANDTYPE=旱地对应地类名称），是否可用须与变更调查/项目资料核对。
4. **项目名口径冲突待核**：项目名为"示例区2025年度第一批耕地恢复"，但 XMBH=F99000120260000 的年度码是 2026、PURPOSE 写"开垦"；另据 shp.xml 血缘，给 XMBH 赋值的源图层名为"示例市示例区2026年第一批次补充耕地9个地块shp"，与文件名年度也不一致。须凭验收备案资料确认后再填 XMMC、XMBH、BCFS、BCGDLY，不能按文件名或元数据任一方直取。
5. 地类编码（DLBM/BGQDLBM）本页不给已核实值；工具按地类名称映射推导（如旱地→0103）时只能记 DERIVED，仍须与变更调查地类字典核对；地类名称"旱地"只作名称线索。
6. **面积口径实测教训**：源几何中 22、111、1 号图斑带内环（孔洞）。若把 TBMJ 直接取几何净面积，会分别少算 441.77 m²、837.49 m²、539.4 m²，并出现 TBMJ = TBDLMJ 的口径矛盾。正确做法：TBMJ 取外环毛面积合计，KCMJ 取孔洞合计，TBDLMJ 取几何净面积（= TBMJ − KCMJ）。
7. **多部件实测**：上述 22、111、1 号是"单部件带孔洞"，不是注6 禁止的多部件。ArcPy 实测（外环+孔洞）为 `partCount=1`、`isMultipart=True`、面积 96.002/100；只有 `partCount > 1`（两个分离外环）才是真多部件。原判据把带孔洞误报成多部件，已确认并改按 `partCount`（qa.py 已修复，新增 `hole_ring_review` 只作孔洞提示，不判 FAIL）。
8. **实测产出与状态（2026-11-03 20:15 重跑；首跑因 TBMJ 误取净面积、qa 误报多部件已作废并删除）**：gdb 9 个面要素、CRS EPSG:4524；29 字段读回全一致（读回 33 = 29 + OBJECTID/Shape/Shape_Length/Shape_Area）；partCount 全为 1（真多部件 0）；area_check 最大差 0.0049 m²（≤0.01，容差为工具设定）；值域违规 0；TBMJ 毛面积合计 124441.86 m²、KCMJ 孔洞合计 1818.66 m²、TBDLMJ 净面积 122623.20 m²；字段状态 CONFIRMED 4 / DERIVED 7 / ASSUMED 3 / MISSING 15。`qa._check_appendix_c` 对附录C 层的自动结论是 FAIL，原因是 10 个必填字段×9 要素全空（不是工具错），须补齐《待补清单》15 行后重跑；以上均为底稿状态，不等于业务验收。

字段状态口径（工具与人工共用一个说法）：

| 状态 | 含义 | 处理 |
|---|---|---|
| CONFIRMED | 源数据或移交资料直接可得 | 直接填，记来源位置 |
| DERIVED | 按规范规则或标准码推导（如面积重算、后缀编号） | 填，须与变更调查核对 |
| ASSUMED | 业务推定，需业务确认 | 填入但必须带确认人/依据，否则降为 MISSING |
| MISSING | 无来源 | 留 NULL，进《待补清单》 |
