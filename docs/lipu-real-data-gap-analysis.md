# 荔浦真实地理数据包实测与插件差距

日期：2026-10-20。数据来源为《荔浦芋-稻轮作永久基本农田生境保护与可持续发展案例数据集》（DOI：10.3974/geodb.2023.06.02.V1）。数据研究目录：`temp/real_data_lipu_20261020/`。数据只用于本地适配性研究；发布页面要求引用来源，转发/再分发需要书面许可。

## 数据包结构

- 下载归档：34,067,769 字节，RAR 完整性检查通过，SHA-256 记录在 `source_manifest.json`；解包后 101 个文件、147,292,122 字节。
- 内容包括荔浦/修仁边界、河网、水质点、土壤采样点、土壤/地形/土地利用/NDVI 栅格、质量检测表、照片和管理文档。
- 数据集发布信息列出约 140 MB、SHP/XLSX/DOCX 等格式及四类专题内容；本地归档还读到 TIFF、ASC、JPG、TXT 等格式。
- 它是永久基本农田芋稻轮作研究案例，不是补充耕地质量验收完整项目；未发现 DWG/DXF、RTK 原始观测、补充耕地移交图斑、项目批复或验收签章资料。

## 遥感数据带出的具体缺口

- 数据包含 `NDVI202107Xiuren.tif`（10 m 单期 NDVI）、`LanduseXiuren.tif`（10 m 土地利用）、10 m 土壤有机质/全氮和 30 m 高程/坡度分类。单期 NDVI 没有红光/NIR波段与第二时相，不能直接输入现有 NDVI 时序变化工具，也不能当作真实验收质量结论。
- 多数 TIFF 使用 `Sphere_ARC_INFO_Lambert_Azimuthal_Equal_Area`（球面基准、WKID=0）；部分 ASC 栅格没有可识别坐标系。论文与可读元数据列出数据专题和文件类型，但没有声明这些栅格 WKT 与修仁乡 CGCS2000 矢量之间的基准转换。ArcPy 可读出 TIFF 内嵌完整自定义 WKT；仅 WKID=0 不等于“无坐标”。
- 预检已批量扫描常见栅格和图像格式、CRS WKT、像元大小、范围、逐波段 NoData、旁置文件及读取错误，并能枚举 CRF 目录和 FileGDB 栅格。初版在荔浦包中列出19个栅格/图像候选，其中11张普通专题图 JPG 与2幅 ASC 都被归为“缺坐标系”。随后按真实数据修正分类：11张无空间参考且没有常见世界文件的 JPG 标记为 `REVIEW_IMAGE_NO_GEOREFERENCE`；真正阻断空间分析的是2幅坐标系未知的 ASC；6幅 GeoTIFF 带完整自定义 WKT。遥感核心比较完整 CRS 身份：标准坐标系按 WKID，自定义坐标系按规范化 WKT；所有输入和评价单元必须配对核对后，才能在同 CRS 内处理。ASC 中确实没有 CRS 定义的两幅栅格仍阻断；不能给它们猜 EPSG。跨自定义球面 CRS 与 CGCS2000 的投影仍需来源说明或控制点依据。
- 需要把“单期专题图层导入与叠加”同“多时相 Sentinel NDVI 变化筛查”作为不同操作：前者服务于空间背景和分层布点研判，后者必须有产品波段、比例因子、日期、云/影处理与可比性记录。

## 真实修仁边界与 Sentinel-2 联跑

2026-10-20 从 [Earth Search STAC API](https://earth-search.aws.element84.com/v1/api.html) 检索到荔浦修仁附近的 Sentinel-2 C1 L2A 影像，并按案例包中的修仁乡真实边界裁剪了本地小样。影像元数据与资产链接分别保存在 `temp/real_data_lipu_sentinel_20261020/before_items.json`、`after_items.json` 和 `manifest.json`；前期为 S2C（2026-10-08），后期为 S2B（2026-10-13），相隔5天、平台不同。红光 B04、近红外 B08 为10 m，SCL为20 m；反射率 scale=0.0001、offset=-0.1，坐标系 EPSG:32649，处理基线05.13。STAC 项目链接：[前期影像](https://earth-search.aws.element84.com/v1/collections/sentinel-2-c1-l2a/items/S2C_T49QDG_20261008T031125_L2A)、[后期影像](https://earth-search.aws.element84.com/v1/collections/sentinel-2-c1-l2a/items/S2B_T49QDG_20261013T031635_L2A)。

- ArcGIS Pro 3.1.5 / ArcPy 对两期真实 B04/B08/SCL 与修仁乡真实边界执行了插件 NDVI 核心；产生前后期 NDVI、差值 GeoTIFF、分区 CSV 和溯源 JSON。测试输入地块是真实乡镇案例边界，不是补充耕地项目验收单元。
- 评价区栅格化为1,194,932个像元，SCL/NoData掩膜后两期共同有效747,608个，有效覆盖率62.5649%；前期均值0.768331、后期0.744937、均值差-0.023393。结果状态为 `NEEDS_FIELD_REVIEW`，不能解释为质量等级或验收结论。
- 单网格小样的 SCL NoData 各有395,725像元，说明单景目录项没有完整覆盖整个修仁边界；画面场景云量字段也不能替代项目区实际覆盖检查。随后新增显式 Earth Search STAC 搜索、完整分页标记、同日期/平台/基线分组、AOI足迹几何覆盖率与相邻瓦片裁切/镶嵌工具。目录检索仅是云端元数据请求，必须确认会发送 AOI；有效像元覆盖率仍由裁片及 SCL/NDVI 统计检查。
- 使用修仁边界交界附近截取的3.14 km²小样 AOI，检索到2026-10-08 S2C与2026-10-13 S2B各两块瓦片，组内足迹几何面积覆盖率均为100%。Pro 3.1.5 / GDAL 3.4完成前后期 B04/B08/SCL 六个裁片和 NDVI+SCL单元统计；10m层200×200，20m SCL 100×100；ArcPy读回 CRS WKID 32649。单元有效覆盖率98.4821%，两期SCL NoData各120像元，输出 `NEEDS_FIELD_REVIEW`。在线处理受公网响应影响，全修仁 AOI 试跑因后期 B08 请求长时间停滞而手动中断，未形成完整乡域成果；唯一运行目录留有未完成 scratch。
- 此次实测暴露并修复统计口径缺陷：原总览把评价单元外矩形像元一并统计。现已将 NDVI/差值输出限制在评价单元内，并把总览有效像元数与分区统计统一；SCL NoData 与分类像元计数分开报告。修复后 Pro 复跑得到总览与唯一分区均为747,608个有效像元，输出栅格评价区外有效像元为0。
- 两期使用不同 Sentinel 平台，且后期场景云量更高；NDVI差值仍可能受大气、薄云、物候和太阳几何影响。本联跑只验证真实数据接入、SCL处理、空间掩膜和证据链，不能校准地面采样或验收阈值。

复现脚本：`temp/build_lipu_sentinel_real_sample_20261020.py`、`temp/run_lipu_sentinel_real_probe_20261020.py`、`temp/verify_lipu_sentinel_real_output_20261020.py`。结果核验：`temp/real_data_lipu_sentinel_20261020/plugin_real_boundary_qa.json`。本地裁剪栅格约9.6 MB；保留 STAC 元数据及源 URL，未下载整景。

## 全包预检器与空间覆盖补充实测

- 当前插件核心在 ArcGIS Pro 3.1.5 对同一官方包复跑，发现19个栅格/图像候选：6个 TIFF 为完整自定义 WKT（`REVIEW_CUSTOM_CRS`），2个 ASC 无 CRS（`BLOCKED_UNKNOWN_CRS`），11张无世界文件且 ArcPy 读不到空间参考的 JPG（`REVIEW_IMAGE_NO_GEOREFERENCE`）。JPG 可留作报告/附件预览；空间分析仍需先找到配准信息。JSON/CSV复核记录：`../temp/realdata_lipu/plugin_audit/遥感数据包预检_20261020_120433_b4b8daa1_结果.json` 与同名栅格清单 CSV。
- 修仁乡面、130个土壤样点、36条河流、5个水质点均可由 ArcPy 读取。`CheckGeometry` 在河流线要素中报告30条“短线段”；这是需要工程人员看图确认的质量提示，不应未经审查就自动修复。该包没有项目地块属性映射规则，因此这些河流记录不代表验收图斑几何问题。
- 六个 XLSX 共11个工作表，包含标题行、中文/英文说明、多行表头和合并单元格。当前核心只把 XLSX 作为汇交附件纳入文件清单，没有面向这类异构工作簿的结构化导入/表头识别；以后导入必须让操作人员确认工作表、表头行、单位和字段映射，不能把标题行直接当数据库字段。
- 以土壤样点与10米土壤有机质栅格做了只读像元取值探针：当前默认投影路径下130点都落入栅格矩形，但只有24点取到非 NoData 值，106点命中 NoData。由于样点为 WGS84、栅格为自定义球面 WKT，ArcGIS未列出可用地理转换，且没有控制点资料，这个比例只能提示需核对掩膜/配准/数据源，不能据此判定栅格覆盖率或样点错位；不得静默把24个值当作全部样点代表值。
- 数据包与前述 Sentinel 样例的覆盖分工：荔浦包有10米单期 NDVI 与专题分类栅格，但没有可直接还原的原始 Sentinel-2 多光谱时相；现有真实 Sentinel 测试包补足了 B04/B08/SCL 时相处理。二者都没有补充耕地项目的竣工边界、CAD/RTK 原始记录、采样链、检测报告与签章附件。

## 下一步实现顺序

1. **已实现并运行**“遥感数据包预检”工具：递归识别常见栅格文件、CRF 目录与 FileGDB 栅格数据集，输出逐波段 NoData、像元、范围、坐标系/WKT和 CSV/JSON 清单；荔浦包当前扫描得到19个候选：2个未知 CRS 栅格、11张待核地理配准的图片、6个带完整自定义 WKT 的 TIFF，未改写源数据。
2. **已实现并在 Pro 实测**自定义 WKT 同 CRS 支持：用 ArcGIS Pro 3.1.5 合成的 4×4 栅格与同 WKT 面要素运行时序核心，16/16 像元参与统计，NDVI 均值变化为 0.2；真实 Sentinel 既有流程回归结果保持一致。另已用荔浦修仁真实边界和两期真实 Sentinel 影像运行核心，验证 SCL、NoData、单元内像元掩膜与统计读回。此验证只证明工作流可运行，不提供到 CGCS2000/WGS84 的法定测量基准转换参数。
3. **下一步**提供坐标资料核验表与负责人确认记录；未得到可靠控制资料前，自定义球面 WKT 不直接与 CGCS2000/WGS84 工程面叠加或生成跨坐标系统计结论。
4. 支持已确认单期 NDVI、土地利用、坡度和土壤专题栅格只读入图、按评价单元统计覆盖/分区面积并用于现场核查线索；报告明确来源、年份、分辨率与限制。
5. 已实现 STAC 搜索、足迹几何覆盖率、相邻瓦片镶嵌、处理基线/CRS检查和人工选景后的 NDVI+SCL运行；Add-In 1.14把每波段 GDAL工作放入独立 ArcGIS Pro Python进程，父进程可以实施硬截止、报告进度和清理失败目录。真实修仁公网重跑遇到 COG TIFF tile读取错误后正确失败清理；网络稳定性及六波段成功链仍需复测，Ribbon仍需在 Pro桌面会话确认。
