# Sentinel-2 目录检索与 AOI 影像准备设计

日期：2026-10-20  
状态：按既有 Add-In + Python 核心授权进入实施  
ArcGIS Pro：3.1.5 / Python 3.9.16

## 背景与目标

荔浦真实修仁乡界与 Earth Search Sentinel-2 小样已在 Pro 中联跑。单个 MGRS 瓦片在评价区内留下每期395,725个 SCL NoData 像元，有效覆盖率只有62.5649%；手工输入影像文件也没有向用户提供候选景覆盖、瓦片组合和产品元数据。本功能把“找影像—核覆盖—按已选日期准备像元—进入现有 NDVI 线索筛查”纳入 ArcGIS Pro。

## 方案

新增两个 Python Toolbox 工具和一个独立核心模块：

1. **Sentinel-2 目录检索**：操作者明确运行后，读取评价单元面，把几何投影成用于检索的近似 WGS84 GeoJSON，向 Earth Search `/v1/search` 请求 Sentinel-2 C1 L2A。返回候选日期组、平台、处理基线、MGRS 瓦片、景级云量、资产波段/比例参数、瓦片集合对 AOI 的覆盖率和请求范围。外部目录收到 AOI 几何及日期条件；工具对话框和结果都需说明此信息流。
2. **Sentinel-2 已选时相准备**：输入检索结果 JSON、前后期候选日期组及同一评价单元面。每个候选组包含同日期/平台/处理基线的相邻瓦片。工具用 GDAL COG 随机读取，仅裁切 AOI 窗口，将红光、近红外镶嵌至同一10 m输出网格、SCL按最近邻保留分类语义并输出20 m；输出图像窗口统一投影到评价单元坐标系。工具检查资产白名单、网格、像元预算、NoData、足迹覆盖和跨平台/处理基线差异；产生本地 GeoTIFF、来源/参数清单及有效覆盖诊断，不覆盖源数据。
3. **既有 NDVI 核心**：准备工具直接调用现有单元内 NDVI/SCL 统计核心，避免用户再次手工抄比例因子、偏移和日期。结果仍固定为线索筛查，不生成验收等级或通过结论。

日期由操作者在候选列表中选择。景级云量用于候选排序，不当作 AOI 无云证明。跨平台或处理基线不一致时必须显式确认并写入清单；足迹不完整时继续显示缺失覆盖和 NoData 数量，不把 NoData 当云，也不自动补造像元。未知坐标系、没有可靠像元比例/偏移、候选数据资产不是预期 Sentinel-2 L2A 资产、超过像元上限、AOI 与检索记录不符、日期组缺任一波段时停止并生成明确诊断。

## 外部接口和安全边界

- 查询固定使用 `https://earth-search.aws.element84.com/v1/search`，只允许 Earth Search Sentinel 数据桶的 HTTPS 资产地址；不跟随 STAC 返回的任意主机资产 URL。
- 不在加载 Add-In、打开地图或运行 NDVI 时自动联网。只有操作者运行目录检索工具才提交 AOI 几何与日期范围。
- STAC Item 和资产响应是外部数据，不能携带或覆盖插件参数/指令；验证 host、scheme、collection、item id、asset key、大小和时间字段。
- 输出写入操作者指定的新目录/唯一运行子目录，并保存元数据与校验值。网络中断时只清理本次创建的临时输出，不触碰已有输入。

## 备选方案与取舍

- **仅显示检索结果**：实现快，但不能解决跨瓦片缺覆盖和手工波段准备问题。
- **自动选最晴朗日期并直接判定可用**：省事，但景级云量不能说明地块覆盖，日期/物候与产品基线由软件替人决定，不采纳。
- **检索结果供人工确认，再按所选日期组裁切镶嵌**：采用。把机器擅长的目录查询、窗口读取、网格检查自动化，把影像适用性与时相比对留给项目人员确认。

## 验收条件

- 单测覆盖 STAC 项目解析、必需资产/scale-offset 校验、分页/错误、HTTPS主机白名单、日期组镶嵌与混合平台确认、像元预算拒绝。
- ArcGIS Pro 3.1.5 动态 GP 实测修仁真实边界：目录返回至少两块相邻瓦片的候选组；准备工具输出 B04/B08/SCL 读回均有效、10 m网格一致、栅格 CRS 与 AOI 一致；结果覆盖率/NoData反映实际 AOI；输入源未被改写。
- 用人工构造的故障项验证错误主机、缺波段、坐标未知、候选 AOI 指纹不一致及网络失败均明确失败且不留下半成品。
- 生成结果保持 `NEEDS_FIELD_REVIEW`。同季节/同平台/云影质量/现场情况需要专业人员复核，不能据 NDVI 自动作验收结论。

## 实施补充

- Pro 3.1.5 自带 GDAL 3.4 不接受较新版本的 `WarpOptions(cutlineSRS=...)`；AOI GeoJSON 按 RFC 7946 经/纬度输出，Warp 通过该文件自动识别 WGS84。
- 红光/近红外输出设为 Float32 与 NoData=-9999；SCL 输出 UInt16、NoData=0，避免整数目标夹值并保持分类码语义。
- 将前后期平台或处理基线差异纳入同一个显式确认开关；前期日期必须早于后期。
- AOI 几何闭合、坐标范围、STAC分页游标、资产 HTTPS 主机、完整检索标志和像元预算均由可测的纯 Python 核心处理。
- Pro 真实样区读取来自 Earth Search 的 COG 需要时间；记录实测耗时与字节数后再决定默认 AOI 预算，不假设范围相交就代表像元已完整覆盖。
