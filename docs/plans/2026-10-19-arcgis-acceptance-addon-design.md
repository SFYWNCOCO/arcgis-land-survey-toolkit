# ArcGIS Pro 补充耕地质量验收功能区插件设计

日期：2026-10-20（随版本更新）  
状态：Add-In 1.14 已打包并注册到当前用户；增加单波段GDAL子进程、父进程硬截止/进度/失败清理。Sentinel-2 STAC检索、多瓦片准备与NDVI+SCL既有小样已跑通；新子进程控制在 ArcGIS Pro 3.1.5 启动验证，真实公网重跑遭遇GDAL TIFF tile读取错误后正确失败清理；1.14 Ribbon加载和按钮交互仍未在当前桌面会话确认  
目标版本：ArcGIS Pro 3.1.5  

## 目标

开发可安装的 ArcGIS Pro `.esriAddInX`，在功能区提供“补充耕地验收助手”。用户从项目工作流入口创建数据库、接入边界/CAD/RTK、设计混合样与容重样、执行质量检查、整理汇交目录，减少重复选择工具和漏填记录。

## 用户与工作场景

主要用户是县级耕地质量评价人员、外业采样员和 GIS 制图人员。工作空间按真实项目管理，操作必须显式区分“设计”“实采”“审核”；真实边界与样品数据由用户提供。样例数据、默认坐标带、示意点不得自动变成正式成果。

## 架构

采用 C# ArcGIS Pro SDK 功能区插件 + ArcPy Python 地理处理核心：

- C# Add-In 负责 Ribbon Tab/按钮；当前实现为按钮打开随包 Python Toolbox 的 ArcGIS Pro 原生参数对话框。当前版本尚未实现自定义向导、自动读取当前地图选择或结果导航。
- 配套 Python toolbox 负责 ArcPy 运算和规则检查；只复用与补充耕地验收数据结构相符的 `setup_quality_gdb.py` 和 `delivery_package.py` 部分能力。`bootstrap_project.py`、`ingest_cad_rtk.py`、`qa_delivery.py` 面向另一套国土调查制图标准，不作为验收业务规则或主质检入口。
- 通过 ArcGIS Pro SDK `Geoprocessing.OpenToolDialog` / `ExecuteToolAsync` 调用 Python toolbox，使运行进入 Pro 原生 GP 历史、消息和进度体系。工具箱及资源随安装包一并部署，插件启动时验证资源路径与版本。
- 标准参数继续从 `config/standard_profile.json` 和广西 v1.1 读取；不把阈值复制到界面代码。

## 功能区与首版功能

Ribbon Tab：`补充耕地验收`；组：`项目`、`数据接入`、`遥感核查`、`采样设计`、`质检与汇交`。

1. **新建项目/GDB**：收集行政区、项目号、项目类型、项目资料确定的 EPSG、输出目录；运行前预览目标路径和数据库结构；同名输出拒绝覆盖。
2. **数据接入**：导入/检查图斑 GDB、CAD、RTK CSV；源图斑只读保留，投影选择基于项目资料，输入不完整时显示明确错误。
3. **评价单元与采样设计**：依据 6.1.1–6.1.4 记录地形部位、土种、补充耕地来源、土地利用现状的划分复核项；原则上每单元不大于 50 亩，每单元至少 3 个混合样分样点，每个图斑至少 1 点，按网格均匀布点。按 6.2.4 生成可编辑设计点：混合样每单元原则 1 份、采样深度 0–20 cm、分样点间距一般不小于 15 m；小图斑例外要求覆盖并避开田边且由人确认。容重样单独建层，在质地构型调查点附近 2 m 范围布设 3 个平行样、平行点间距 2 m，使用 100 cm³ 环刀。污染风险样按风险源另行评估，不套用统一点数。输出始终标记为“设计点”。
4. **现场回填（未纳入首版）**：后续导入 GNSS 实测坐标/采样记录，关联设计点并留存调整理由、照片与样品流转号；不能把设计点直接改名为实采点。
5. **数据库结构检查**：检查附录 G 图层/字段合同/坐标系/评价单元 50 亩上限，以及附录 C 鉴定图斑字段、显式数值约束、空值、标识码重复、编码值复核项和几何要求。附录 C 注 6 明确禁止多部件图斑，工具遇到多部件图斑判为不通过并列出标识码；规范未给细缝宽度阈值，故将“不得利用细缝连接多个图斑”列为强制人工拓扑/影像核查项，不自行套用外部阈值。独立“混合样设计点空间质检”工具核对单元/图斑最低点数、设计点与关联图斑包含关系并报告15米间距短缺；均匀度、避边和现场条件仍须复核。实采点回填仍未实现。
6. **汇交准备**：按附录 I 初始化目录并检查目录/文件存在性；数据库具体内容、图件、文字成果、附件证据、签字、CMA 资质和照片合规性等均须人工审核，不因空目录存在就判材料完成。
7. **遥感线索筛查**：现已加入显式Earth Search目录检索、分页完整性、波段元数据读取、同日期/平台/处理基线候选组、足迹几何覆盖率、相邻瓦片裁切/镶嵌及NDVI+SCL单元筛查。公开服务不稳定或大范围读取停滞时不标记成功；不定义规范未给出的NDVI阈值，不自动判地类、质量或验收。真实乡域处理及Add-In桌面按钮仍需现场环境复核，细节见 `docs/remote-sensing-workflow.md`。

## 数据流

真实源材料只读预检 → 新建项目工作库 → 复核评价单元 → 生成并人工校正设计点 → 外业采样并回填实测记录 → ArcPy 规则质检 → 人工审核 → 汇交目录和日志。每次处理生成运行 ID、时间、工具版本、输入、输出、参数、GP 消息和状态。所有新建数据写到明确输出位置，不覆盖源数据。

## 采样校验约束

按广西 v1.1 执行：评价单元原则上 ≤50 亩；每评价单元混合样至少 3 个分样点，且每图斑至少 1 点；网格均匀布点；分样点一般间距 ≥15 m。小图斑无法满足 15 m 时，仍需至少 3 点尽量覆盖全图斑、避开田边并记录人工复核。混合样取 0–20 cm，每单元原则上 1 份。每评价单元原则 3 个容重平行样，在质地构型调查点附近 2 m 范围内取样，平行点相隔 2 m，使用 100 cm³ 环刀；不是每个混合样分样点都生成一组三个容重样。污染风险样按项目污染风险另行判断。所有现场校正均留痕，不把算法方案伪装成实际采样事实。来源：指导书 6.1.1–6.1.4、6.2.4.2–6.2.4.3，印刷页 8、16（PDF 页 14、22）。

## 已识别的现有代码边界

- `setup_quality_gdb.py` 建立附录 G 评价单元空库，可复用其字段契约；导入国土变更图斑和质量鉴定图斑必须原样保留。
- `delivery_package.py` 的目录初始化和部分文件检查可复用，但不得把其当前无条件必交的 CMA/原始记录等项目作为普遍硬失败；第 10.4(2) 将其列为其他资料。污染检测报告须按指南所列情形人工确认适用性。
- `qa_delivery.py`、`bootstrap_project.py`、`ingest_cad_rtk.py` 依照 `standard_profile.json` 的国土调查制图标准，不接为本插件验收 QA。200/400/600 m² 制图阈值不能用于否决补充耕地验收图斑。
- 自动质检可以核对结构、字段、几何和空间关系；评价单元同质性、样点代表性、踏勘真实性、照片真实性、CMA 资质范围和专家意见必须保留人工审核。
- **当前实现边界**：结构质检已覆盖附录 G、附录 C 字段/显式取值及评价单元 50 亩上限；混合样设计点最低点数、关联图斑包含关系和一般15米间距已可单独运行空间质检，但它不验证均匀网格、避边、代表性或现场可达性；实采点回填、正式专题图和正式文字报告自动生成仍未实现。汇交检查主要核验目录、文件类型和照片分类线索，不替代材料内容审阅、比例尺/图例/签章核验。

## 界面、异常与安全

- 当前按钮将打开 Pro 原生 GP 工具对话框；参数、进度和消息由 GP 工具处理。插件自定义项目检查、任务进度面板、日志导航和结果摘要面板仍未实现。
- Python Toolbox 参数层对多数工具执行前检查坐标系、字段、输出覆盖和输入格式；数据类型/规范条件不足时返回中文错误或 `NEEDS_REVIEW`，不宣称完整验收通过。
- 默认无覆盖；对可能替换数据的操作先输出到新数据集，确认比较后才允许用户手动接纳。
- 处理中断时保留输入和日志；临时产物使用唯一运行目录；避免对已打开的 GDB 执行删除/覆盖。
- 无真实边界、测量坐标、实验室报告或正式符号库时，结果状态必须为 `UNVERIFIED` 或“待人工审核”。

## 兼容性与安装

机器检测为 ArcGIS Pro 3.1.5、ArcGIS Pro Python 3.9.16、Visual Studio 2022 Build Tools 17.14、.NET Runtime 6.0.8。使用 Pro 3.1 目录中的 SDK assemblies 和私有 .NET SDK 6.0.427 编译；本机 Build Tools 缺少 .NET SDK resolver，且 Esri targets 的 `CodeTaskFactory` 不支持其 .NET MSBuild 通道，因此首版改为 PowerShell 按 Add-In ZIP 目录结构打包，再用 Pro 自带 `RegisterAddIn.exe` 注册到当前用户。该限制和实测结果记入 `addin/README-build.md`、`addin/verification/verification-record.md`。不升级 ArcGIS Pro，不修改全局 Python 或 VS/Pro 安装。

## 首版完成标准

- 生成可安装的 `.esriAddInX` 和与之配套的 Python toolbox/必要资源说明。
- 插件可在 ArcGIS Pro 3.1.5 中加载，显示功能区入口，并能成功打开/运行首版工具。
- 项目建库、数据接入、采样设计、质检与汇交入口都有清晰参数和运行状态；错误时能读到中文错误与日志。
- 在合成测试项目上形成可复查的设计点/质检报告/汇交检查结果；示例输出保留模拟标记。
- 对真实数据验证只使用用户明确提供的副本，所有原始源文件保持不变。

## 未包含事项

首版不自动判定地块权属、实际土地利用、土壤等级或污染是否合格；不自动生成未经审核的正式结论/签章；不承诺无需现场人员校正即可直接采样；不改动用户 GIS 全局配置。

## 主要风险

1. Pro 3.1 SDK 未安装可能阻塞 Add-In 编译；按官方 3.1 SDK 安装后再继续。
2. 打包工具箱资源路径需在目标 Pro 3.1.5 环境验证；路径不可用时插件应清晰提示并禁止静默降级。
3. 真实项目坐标带与输入资料一致性由用户确认，不能用默认经度替代项目 EPSG。
4. 采样规则如与主管部门针对项目的书面意见不同，以适用文件和书面意见为准并记录版本。
