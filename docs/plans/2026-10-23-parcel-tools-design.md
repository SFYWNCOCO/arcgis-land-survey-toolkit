# 地块工具设计

用户已确认开发质检、整理、自动制图，并提出无法快速定位地块。交付为现有 ArcGIS Pro 3.1 Add-In 的新增“地块工具”分组。

## 目标态

- 快速定位：独立无模式窗口，选择当前地图中的面图层和编号字段，默认识别 DIKUAI_NO / DKBH / BSM；精确查询优先，可切换包含查询。列表显示图层、编号和 OID，点击定位按钮或双击结果，选中并缩放。多图层同号不直接挑选第一条。切换地图后刷新图层。
- 一键质检：输入面图层、编号字段、可选必填字段及面积字段/单位/计算方法/容差。输出 FileGDB 异常面和 UTF-8 CSV/JSON。几何、重复号、空值、重叠与面积口径分开；不把全空备注或不同面积算法直接判错。
- 数据整理：复制到新的 FileGDB 要素类；可选坐标系和明确的转换方法；映射/补充字段使用显式 JSON 规则；新增平面/椭球平方米、公顷、亩字段。已有属性保留，输出同名拒绝覆盖，失败清理本次输出。
- 自动制图：从当前工程保存临时副本，使用内置 A4 横向模板，输出总览和按编号逐地块 PDF。显示图名、编号、面积口径、坐标系、比例尺、指北针、图例及日期。可指定已有 .pagx。原工程不保存变更。

## 结构与顺序

现有 C# Add-In 增加定位窗口、四个按钮；三个处理按钮打开独立 ParcelTools.pyt；ArcPy 核心放 acceptance/parcel_tools.py。复用现有打包、注册入口，补入新工具箱与模板。先定位，再数据处理，最后出图与打包。

## 数据与风险

- 原始 Shapefile 只读；新成果放用户选定输出目录。
- 9 个真实地块 DIKUAIAREA 等于椭球公顷四位小数；约 55.2 平方米差值是平面/椭球口径差异，不认定为异常。
- 无 CRS、转换方法不明确、编号为空/重复影响单图命名、输出冲突时明示错误。
- UI 点击链此前受电脑工具截图超时影响，构建和 ArcPy 实测不能冒充 UI 已验证。

## 验收

真实数据按椭球口径不报面积错误；构造重复号/空值/重叠和无 CRS 对照必须报出。整理后源哈希不变，输出数量/CRS/字段/面积读回。导出总览+9张地块 PDF 并检查页数和图面。C# 编译、包内 SHA256、安装读回分别记录。定位窗口须在 Pro 中验证输入39能选中并缩放到39号地块；UI不可用则明确保留该项。
