# 地区与场景适配评估（对照课件 v1.1 与插件 1.76）

日期：2026-11-01。依据：《广西补充耕地质量验收作业指导 1.1》课件 93 页（`D:\work\广西补充耕地质量验收作业指导1.1-课件.pdf`）、作业指导书 v1.1（79 页），以及本仓 `acceptance/`、`config/` 现有实现。只写已核对的事实；推断处标「推断」。

## 结论

插件已经把广西一套流程做成可运行闭环：单元划分 → 布点 → 出图 → 表格 → 交付自检 → 质量核算 → 等级评价。**地区差异只落地两套参数，场景只覆盖「项目类补充耕地验收」一条线**。跨地区要补的是「地区包」，跨场景要补的是「场景开关」，而不是改代码逻辑。

## 二、地区差异的四个层次

地区不是只换坐标系，课件 p56 已明确「北海市属华南区-粤西桂南农林区，12 个评价指标」，不同大区的权重、隶属函数、等级划分线都不同。

| 层 | 差异内容 | 插件载体 | 现状 |
|---|---|---|---|
| 1 行政区→农业分区 | 县 → 二级农业区 → 大区 | `config/region_counties.json`（111 县、3 个二级区） | 有，映射到 `华南区/西南区/长江中下游区` |
| 2 等级评价参数 | 12 指标权重、数值型隶属函数、概念型隶属度表、等级分带 | `config/grading_parameters.json`（华南/西南/南岭三套） | 有，权重和≠1 直接报错 |
| 3 指标阈值 | 符合性/分级阈值、判定方向 | `config/grade_thresholds.json`（仅西南区、华南区两套） | **缺长江中下游区**（南岭 42 县），26 项阈值待补，参考表只有福建省 |
| 4 工程与资料 | 中央经线/3 度带、高程基准、影像源与 GSD、县界、地类编码 | `项目参数.json`、`config/standard_profile.json` | 有参数位，但缺「地区资料清单」校验 |

关键约束：`grading.py` 在缺大区阈值时 fail-closed，不回退相邻区。所以**南岭 42 个县现在跑等级评价会被直接拒绝**，这不是 bug 而是保护。

| 场景 | 与「项目类补充耕地验收」的差异 | 插件现状 |

## 四、以后怎么做：配置驱动，不改主干

**1. 地区包（region pack）**

```
config/regions/<大区>/
  grading.json      # 权重、隶属函数、等级分带
  thresholds.json   # 指标阈值与判定方向
  conformity.json   # 符合性阈值与直接判不合格情形
  layout/           # 图面版式、图名规则、坐标系默认值
  sources.json      # 该地区必须提供的原始资料清单（DOM/县界/土壤图/地形图/检测报告）
```

`项目参数.json` 增加 `county`（或 `region`）一个字段，工具按县自动选包；包不存在时拒绝启动并列出缺哪几项，而不是静默用默认值。

**2. 场景开关**

`项目参数.json` 增加 `project_type: project | non_project`、`stage: design | survey | report | delivery`。前者影响能否跨项目合并、编号规则、培肥责任主体；后者决定插件该做到哪一步，避免把设计资料当鉴定成果导出。

**3. 启动自检**

把 `scripts/verify_rule_configs.py` 扩成「地区包完整性检查」：权重和、阈值覆盖、隶属函数参数范围、必备资料清单；CI 与工作台启动各跑一次。

**4. 资料清单驱动**

每个地区包带 `sources.json`，预检时输出「本次缺哪些资料」（DOM、县界、土壤图、地形图、检测报告、照片），和现在的检查清单同一套出口。

**5. 场景化的交付模板**

交付包（附录 I）目录与表式按场景切换，不把「设计预览」当「鉴定成果」交付。

## 五、最该先做的三件事

1. **补长江中下游区阈值 + 26 项待补阈值**：这是硬缺口，南岭 42 县目前无法出等级结论。
2. **场景开关**：项目类/非项目类、设计/鉴定阶段，防止混用。
3. **检测报告与照片接入**：课件 p52–53、p47–50 要求的两类证据现在是断的，补齐后成果才从「设计资料」变成「鉴定成果」。
