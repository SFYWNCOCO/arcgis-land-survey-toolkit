# 傻瓜式网格采样插件：开发方式调研与本项目设计（2026-10-23）

## 一、结论先行

1. **路线**：继续用「Pro Add-in 薄壳 + Python 工具箱干重活」最省成本；要做"傻瓜式"，关键不是换技术栈，而是把入口从 14 个按钮收敛成 **1 个侧栏面板 + 1 个一键流程**。
2. **网格四套成果可做，且已验证**：方格网 / 网格交点 / 网格中心点 / 设计采样点，在真实 2 个评价单元上跑通（91 格 / 113 交点 / 91 中心点 / 6 个设计点，同单元最近间距 79.98 m）。
3. **影像不需要用户会做图层**：程序按成果范围自动下载影像切片拼成本地 GeoTIFF，再自动加到地图最底层。已出一张完整 A4 图（含真实评价单元与本机影像，因涉密标注未随公开仓库发布）。
4. **真正的坑在出图模板**：模板里的图号、比例尺、方里网注记、面积统计表是写死的占位值，换项目就会"图对不上数"，必须改成按数据动态生成，否则傻瓜式会把错误固化。

## 二、别人怎么开发 ArcGIS Pro 插件

| 路线 | 做法 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| A. Add-in（C#/WPF）+ DAML | 官方 SDK，Ribbon/按钮/DockPane，Esri 社区样例 325 个 | 交互最自由，可做侧栏、实时预览 | 需 VS、.NET、每次改 UI 都要重编译打包 | 要"像软件"的成品 |
| B. Add-in 按钮 → Python 工具箱(.pyt) | 按钮只负责调 GP 工具，业务全在 arcpy | 逻辑改 Python 即可，测试好写 | 界面是 GP 对话框，字段映射/下拉体验受限 | 本项目现状，性价比最高 |
| C. 纯 .pyt 工具箱 | 不做 Add-in，用户自己找工具箱 | 零编译 | 用户找不到入口，不符合傻瓜式 | 内部技术员 |
| D. Pro Tasks（.esriTasks） | 预定义引导流程，无需写代码 | 上手快 | 不能算数、不能动态默认值 | 培训演示 |

本项目 1.21 走的是 B：14 个按钮，每个按钮拉一个 GP 对话框。对没接触过 Pro 的人，问题不在功能缺失，而在：

- 要知道"先建库、再接入、再设计、再出图"的顺序；
- 要会选图层、认字段、判断坐标系；
- 出图还要自己加影像、调符号、选模板。

## 三、同类工具（用户提供的商业方案）在做什么

宣传稿里的可借鉴点：字段可视化映射面板、四套网格成果独立输出、参数保存复用、一键出单元。
不可直接照搬的点：把它当作"自动合规"。50 亩阈值、20 m 网格、每单元 3 点是规范约束或项目条件，界面可调不代表可以随便改；截图里的默认值不是规范值。

## 四、本机实测结论（可复现）

| 项 | 实测结果 | 结论 |
|---|---|---|
| 渔网生成 | 120×80 m 单元、20 m 格 → 24 格、24 个格中心点 | 可直接用模板要素类出格网 |
| 网格交点取法 | 折线渔网取顶点：24 个实例、去重后仅 20 个（直线段只有两端点）；多边形渔网取顶点：120 个实例、去重 **35** 个 = 7×5 正确 | **交点必须从多边形渔网取，不能从折线渔网取** |
| 面积口径 | 同一图形椭球 9419.75 m² / 平面 9600.00 m²，差 1.9%（14.13 亩 vs 14.40 亩） | 成果必须声明口径，不能混用 |
| 在线影像服务 | `addDataFromPath` 加 Esri World Imagery MapServer 与 WMTS Capabilities 均成功 | 机制可用，但正式成果不宜用 |
| 天地图 WMTS | 同法直接加 → `RuntimeError: AUTOMATIC 失败，可能需要提供更具体的 web_service_type` | 需 key + 明确服务类型，未验证，不作为默认路径 |
| MapServer 子图层 | 加一个影像服务一次带进 20+ 个 `*Resolution/Metadata` 噪声图层；批量清理会把影像层一起删掉 | **默认走"下载切片→本地 GeoTIFF"**，不进在线服务 |
| 真实数据跑通 | 2 个评价单元：91 格 / 113 交点 / 91 中心点 / 6 设计点，每单元 3 点，间距 79.98 m | 核心算法可用 |

## 五、傻瓜式设计（建议形态）

**一个侧栏面板，四步，硬件只填三样东西。**

```
┌ 补充耕地采样助手 ─────────────┐
│ ① 选数据  [图斑/单元图层 ▾]   │  ← 自动识别编号字段、检查坐标系
│ ② 布点   网格 [20] m  ☑ 每图斑≥1 ☑ 避边 5m │
│ ③ 影像   ○项目影像 ○天地图 ○演示影像 │
│ ④ 输出   [选择成果文件夹…]     │
│      ┌───────────────┐        │
│      │  一键生成并出图 │        │
│      └───────────────┘        │
│ 结果：2 个单元 / 6 点 / 间距达标 │
│ ☑ 已加载到地图  [打开成果目录]  │
└──────────────────────────────┘
```

关键"傻瓜化"手段（每条都对应一个已知踩坑）：

1. **默认值即合规值**：网格 20 m、每单元 ≥3 点、每图斑 ≥1 点、间距 ≥15 m、避边 5 m。用户只改"网格尺寸"。
2. **自动认字段**：`PJDYBH/DKBH` → 评价单元/图斑；找不到就弹出命名一次，记进项目配置复用。
3. **自动建图层**：方格网、交点、中心点、设计点四套图层由程序创建并符号化，用户不需要懂"要素类/图层"。
4. **影像三级来源**：项目 DOM（首选）→ 天地图切片（需 key，0.5–1 m）→ 演示影像（仅供自查，不得进正式成果）。程序按成果范围下载并拼 GeoTIFF，自动置底。
5. **出图即结果**：自动套 A4 模板、自动缩放（1:10000 或 1:2000 单地块）、自动写图名/图号/日期，逐单元导出 PDF。
6. **一句话结论**：面板底部只显示"2 个单元 / 6 点 / 间距达标 / 3 项待人工确认"，不显示 GP 消息日志。
7. **失败说人话**：坐标系未定义 → "这个文件没带坐标系，请选 CGCS2000 3 度带 36 带"；而不是 000622 参数无效。

## 六、演示成果与已暴露的模板问题

演示图：真实评价单元 + 下载影像 + 四套网格成果（A4 200 dpi），因图面标注密级未随公开仓库发布。

必须修的 5 处（都是"换项目就错"的类型）：

1. 图例里 `Band_1/2/3`、`红色/绿色/蓝色` 噪声项 —— 删项并关同步。
2. 比例尺 1:3000 出现 0.03/0.06 km 小数档 —— 比例尺锁 1:10000，或改米制。
3. 图号、密级、编制单位、日期是模板占位（`XX县`、`×××`）—— 改成项目参数注入。
4. 底部"评价单元面积统计"是模板静态假数据（E0001 旱地 35.1 亩…）—— 必须按实际单元动态生成，否则比没有更危险。
5. 图廓坐标注记写死 GK36 基数，UTM/其他带号数据会错位几十公里 —— 按数据四至动态算注记。

## 七、实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0（已完成） | 网格法四套成果 + 面积口径 + 3 项集成测试 | pytest 3 passed；真实 2 单元跑通 |
| P1 | 影像模块（项目影像/天地图切片→GeoTIFF）+ 图例清理 + 比例尺/图号动态 | 出一张无 Band 噪声、无占位文字的图 |
| P2 | 一键流程（单 GP 工具收口）+ 面板（DockPane 或 GP 对话框最少参数） | 新人 5 分钟内独立跑完一个单元 |
| P3 | 动态面积统计表与方里网注记（模板按数据重算） | 图上数字与属性表逐项一致 |
| P4 | 评价单元四因素自动划分（拆分/合并候选 + 人工确认） | 只在资料齐全的项目启用 |

## 八、未验证与风险

- 天地图 WMTS 直连未通，需用户 key 实测；其成果用于报件时的许可与审图要求未核实。
- 演示用的是 Esri World Imagery（0.5–0.6 m），**只能做自查/演示**，不能进正式报件图。
- Add-in 面板在 Pro 3.1.5 界面上的点击链路仍未端到端验证（1.21 同样存在此缺口）。
- 网格尺寸、避边距离、每单元点数上限属项目参数，软件默认值不等于规范值。
- 面积统计、样点代表性与外业可达性仍须人工复核，程序结论固定为 `NEEDS_REVIEW`。
