# 真实数据包差距核查：补充耕地验收插件遥感链路

日期：2026-10-20  
范围：公开真实遥感产品小样 + 现有 ArcGIS Pro 遥感筛查核心；不把公开影像称作真实验收项目资料。

## 结论

本轮找到并实际读取了覆盖广西南宁武鸣附近的 Sentinel-2 L2A Collection 1 真实影像产品，裁剪出小于 1 MB 的双时相样包，并让 ArcPy 核心在真实影像上运行。真实数据暴露了坐标系转换流程、SCL 云/阴影像元掩膜、STAC/产品元数据自动读取三项关键差距；其中 SCL 掩膜已按实景样本补入并验证，坐标系仍要求用户先按项目资料处理，STAC 元数据自动读取仍待开发。

公开数据源没有提供本项目所需的真实验收原始包（项目批复、自然资源部门图斑、真实 CAD/竣工测量、RTK 原始观测、现场踏勘、土样链路、CMA 检测、签审报告和附录 I 的完整成果）。本次影像只能验证遥感模块，不能验证完整业务验收成果、采样判定、质量等级或报告结论。当前还没有从公开网络找到可合法下载且完整的广西补充耕地质量验收项目全套原始成果；公开公告只描述任务内容和拟交付成果。

## 真实数据揭示的插件差距

1. **坐标处理阻断真实工程使用。** 工程数据库里的评价面是 WKID 4524，Sentinel 产品是 UTM 48N/WKID 32648；当前工具硬性要求完全同 WKID，直接运行失败。手工预投影后可运行，但普通用户无法从工具里知道该怎么选转换、像元网格和重采样。应新增明确的“输出/分析坐标系”策略、可用地理转换列表、重投影记录和对齐选项；涉及精度要求时由项目技术负责人选择转换，不能悄悄改原始成果。
2. **SCL 云掩膜已补入，仍需产品级复核。** 遥感工具新增两期 SCL 栅格输入，按最近邻对齐到红/NIR 网格，排除 NoData、饱和/缺陷、地形或投射阴影、云影、未分类、中/高概率云、薄卷云和雪冰（0、1、2、3、7、8、9、10、11），并在 CSV/JSON 输出全栅格和逐评价单元的排除计数。真实武鸣窗口本身只有 SCL 4/5；另在真实栅格副本中注入类别2像元做了 ArcPy 实跑，4 个重采样后的 10 m 像元被排除。无 SCL 时仍要求操作人员确认已完成云/阴影处理；该勾选不证明处理真实有效。SCL 分类准确率和云概率阈值没有在本模块中校准，须按产品处理基线及传感器文档复核。
3. **元数据仍靠人工录入。** 当前用户需手填日期、产品来源、红/NIR路径、比例和偏移；而真实 STAC Item 含产品 ID、平台、时相、EPSG、10 m/20 m 分辨率、资产链接、NoData、比例与偏移。插件应提供粘贴 STAC Item/选择产品资产的入口，自动带入元数据，并保存原始 Item、处理参数、软件版本和文件校验值。
4. **时相/传感器的可比性没有门禁。** 本次对照跨 35 天且由 S2C 与 S2B 获取。工具目前允许自由选日期和来源，虽在说明里提示风险，但没有要求用户确认时相差、传感器、季节/物候和处理级别。应在运行前形成可读的可比性检查单并允许专业人员记录原因；不对 NDVI 设验收阈值。
5. **业务现场真值不在遥感数据中。** Sentinel 影像无法替代 1:10000 或更高要求下的竣工测量图斑、RTK、踏勘、采样、实验室原始记录和签审。插件完整版本还需 CAD/RTK 导入、坐标审计、点位布设和成果库字段/附录要求逐项质检；这些必须使用真实脱敏业务资料才能验收。

## 已完成的首轮修正与下一轮顺序

- 已完成：Sentinel-2 L2A SCL 双期输入、同 CRS 最近邻网格对齐、无效类掩膜、逐单元排除计数与 JSON 溯源；ArcGIS Pro 3.1.5 / ArcPy 3.9.16 在本样包完成实跑。真实窗口检查类4/5；在真实 SCL 副本注入类2后，端到端统计成功排除4个10 m像元。掩膜分类清单仍需随产品处理基线和任务要求复核。
- 已完成：完整测试集 48 项通过；ArcGIS Pro 3.1.5 实际调用事务式建库，读回项目清单、GDB 与要素类，确认初始化暂存目录无残留。
- 已完成：评价单元临时栅格化改为 `in_memory` 工作区。真实样包的 Python Toolbox 动态 GP 实跑成功，输出状态 `NEEDS_FIELD_REVIEW`、2个评价单元汇总；断言确认成功运行后没有残留 scratch GDB。
- P0：改进坐标转换交互，提供项目技术负责人可选的地理转换方案与处理记录；保留源数据，只投影临时副本。当前仍要求先由用户在 ArcGIS Pro 按项目资料投影评价单元，工具拒绝WKID不一致。
- P1：读取 STAC Item JSON / Earth Search URL，自动识别日期、平台、波段资产、网格、scale/offset/NoData；下载按窗口裁剪并限制文件体量。
- P1：增加多传感器/时相差/覆盖率提示和影像元数据台账；生成遥感核查图层和版面图件。
- P2：拿到经授权脱敏的真实 CAD、RTK、验收图斑、采样台账、实验室报告后，做端到端业务包验收；不能用公开遥感样例代替。

## 2026-10-20 后续复核：当前实现状态与仍存问题

上文“STAC 元数据自动读取仍待开发”和 P1 检索/裁切建议是当时的历史结论。Add-In 1.2 已新增显式启动的 Earth Search STAC 检索、影像候选分组、AOI 足迹覆盖率、多瓦片裁切/镶嵌与 SCL 统计；因此这些事项不再是未实现功能。真实小范围 Sentinel 样例已实跑，但全乡域远程 COG 读取曾停滞，Pro 功能区按钮也尚未在重启后的桌面会话实点，见 [当前遥感流程说明](remote-sensing-workflow.md) 与 [Add-In 验证记录](../addin/verification/verification-record.md)。

本轮根据 v1.1 原文对采样规则作条款拆分：分样点数量与均匀网格依据 §6.1.4（印刷页 8/PDF 页 14）；15 m 间距、0–20 cm 深度和小图斑处理依据 §6.2.4.3(1)（印刷页 16/PDF 页 22）；每单元 1 个混合土样、3 个容重平行样及容重点位关系依据 §6.2.4.2–§6.2.4.3(2)。混合样编号须与评价单元编号相同，容重样编号按 `RZ+评价单元编号`；设计点另存点位 ID/重复序号，不能把内部候选点 ID 当作正式样品标签。

代码加入了采样投影 CRS 显式校验、混合样采样深度字段和规范样品编号字段；ArcGIS Pro 3.1.5 尚未对这批改动重新构建和运行 Ribbon 交互。CAD 转换现在逐类读回输出要素数；无类或零总要素返回 `EMPTY_NEEDS_REVIEW`，Pro 工具报告错误，不得将其视作有效转换成果。该修复的纯 Python 回归检查已增加；ArcPy 对真实 DWG/DXF 的数量统计仍需在 Pro 与真实源件上验证。

CAD/RTK 仍属关键未闭环：真实配准控制点/残差、CAD 图纸单位与带号、RTK 平面轴序与项目区范围、高程类型和垂直基准转换、导入源文件哈希目前没有完整证据链。RTK 含 Z 的点仍不得据此直接当作 1985 国家高程基准成果；需按项目测量记录核实天线高、椭球高/正常高与批准的转换模型。结构 QA 也不替代采样点位、实采状态、样品交接、现场照片和检测结果核查。

当前差距优先级调整为：P0 完成采样字段/条款与空 CAD 结果保护并用 Pro 复核（已完成核心及合成工程复核）；P1 补项目区/控制点范围检查和经过审批的垂直基准转换流程；P2 使用获准的真实广西业务包做 CAD、RTK、评价单元、采样、实验室和汇交成果端到端验收。公开遥感样例和模拟报告不作为实测业务成果。

2026-10-20 后续：CAD 源件及发现的 PRJ/WLD 配套文件、RTK CSV 已纳入接入结果 SHA-256/大小/修改时间清单；RTK 原坐标点层和投影点层同时写入 `Z_STATUS`、`Z_FIELD`、`VERT_REF`，有 Z 字段时明确为 `UNVERIFIED`，不再让数值高程看起来像已确认的 1985 高程基准。ArcGIS Pro 3.1.5 合成 CSV 联跑和属性读回通过。此项缩短了来源追溯和误用风险，但没有增加垂直基准转换，也没有替代真实项目控制点、项目区空间合理性或测量精度检查；这些仍须真实测量资料闭环。
