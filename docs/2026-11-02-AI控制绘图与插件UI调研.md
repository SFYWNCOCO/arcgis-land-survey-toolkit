# AI 控制绘图与插件 UI 调研（2026-11-02）

> 范围：桌面 GIS / 3D 创作软件如何把 AI 助手接入"控制图层、绘图、出图"，以及 AI 侧栏的交互与视觉模式。
> 对象：land_survey_toolkit / ProAiBridge（ArcGIS Pro 3.1.5 C# 插件 + Python 核心 + 自研 AI 桥接）。
> 取证方式：只读源码 + 外部公开资料检索；本文不修改任何源码。
> 证据等级：**已核实**＝读到原始 README/代码/官方文档正文；**推断**＝由已核实事实推导，未直接读到实现；**未证实**＝只有标题/二手描述或检索不到。

## 0. 结论先读

1. **一方基准已出现**：Esri 在 ArcGIS Pro 3.6/3.7 引入内置 **Pro Assistant**，并开放 SDK 扩展点 `AIAssistantExtension` + `[AIAssistantFunction]`，模型通过 **function calling** 自动选择并调用扩展函数（已核实：[Esri ProGuide 镜像](https://github-wiki-see.page/m/Esri/arcgis-pro-sdk/wiki/ProGuide-Create-a-Pro-Assistant-Function)）。这意味着"AI 控制 Pro"不再是社区玩法，而是官方演进方向；本项目走"自研侧栏 + 自带模型"路线，需要主动对齐它的形状（工具=函数+描述、参数=带说明的强类型、结果=结构化回执）。
2. **社区主流是 MCP，不是内置侧栏**：10 个样本里 6 个把能力暴露为 MCP 工具，由外部客户端（Claude/Cursor/Codex）驱动；ArcGIS Pro 侧有两种落地形态——**in-process C# 插件**（快、能碰 Main CIM Thread）与 **Pro Python 窗口桥**（免编译、慢）。Knight60 给出量化对比：进程内 `QueuedTask.Run` 约 **9 ms/调用**，早期纯 Python 方案约 **28 s/调用**（已核实，[ArcGIS-Pro-MCP](https://github.com/Knight60/ArcGIS-Pro-MCP)）。
3. **"能画"的少，"能改属性"的多**：QGIS MCP 系（125 工具版、Blender 系）有完整的要素增删改、几何更新、编辑事务（`start_editing`/`commit_edits`/`rollback_edits`/`undo_edits`）与 checkpoint/restore（已核实，[nkarasiak/qgis-mcp](https://github.com/nkarasiak/qgis-mcp)）；ArcGIS Pro 系的社区样本普遍以图层/属性/GP/出图为主，**几何绘制与编辑工具稀少**，且多数没有强制人工确认。
4. **本项目的地基不差、短板很集中**：47 个工具单真源 `tools.json` + 启动校验 + `readOnlyHint` + `confirm=true` 契约 + 工程/地图守卫 + GP 任务化 + AI 账本，这套在样本里属于**上游水平**；但把 `tools.json` 与本报告样本横向比对，本项目**没有任何几何/要素写入工具**，**没有撤销栈**，**没有"先候选后确认"的 AI 侧预览层**，**没有把图像回读给模型**（`ReviewMapAsync` 已经写好却只服务于人工出图面板），**流式只到状态栏**，**外部 MCP 客户端调用写工具时没有人工确认**。这五点就是"AI 控制绘图"的真正差距。
5. **最短路径不是加工具数量，而是补三层**：建议卡/参数表单（人看得懂）→ 预览/干跑（人看得见）→ 确认与撤销（人收得回）。三者都建立在本项目已有的 `confirm` 契约、图斑编辑 manifest/token、`QueuedTask` 执行器之上，不需要重写架构。
6. 网络限制：本机直连 `github.com:443` 失败（curl 超时），GitHub 正文通过 `raw.githubusercontent.com` 与 `github-wiki-see.page` 镜像取得；镜像内容按"官方原文镜像"标注，未与 GitHub 线上页面逐字比对。

## 3. 逐样本要点

### S1 ArcGIS Pro 内置 Assistant + Pro SDK 扩展点（一方基准）

**已核实**（[ProGuide 镜像正文](https://github-wiki-see.page/m/Esri/arcgis-pro-sdk/wiki/ProGuide-Create-a-Pro-Assistant-Function)）：

- Pro Assistant 内嵌于 ArcGIS Pro，"uses artificial intelligence to answer your questions, generate queries, and perform actions"。
- 扩展模型：`internal class X : AIAssistantExtension`，内部每个能力是 `public static` 函数，返回 `AIFunctionResult`，标注 `[AIAssistantFunction, Description("...")]`；**函数与其参数的 `Description` 就是给模型的工具说明**——即"工具 schema 即提示词"。
- 机制：Pro Assistant 用 LLM 的 **function calling** 决定调哪个函数、传什么参数，然后自动调用；实现体就是普通 Pro SDK 公开 API（与 addin 无差别）。
- 部署前提：Pro 3.6 + **ProAssistant.msi**（随 Pro 安装的可选 AI 模型安装项）+ 组织在线管理员设置（AI assistant / 允许 Esri Beta 应用）；401 多为门户权限问题。
- 官方示例能力：用当前地图**创建布局**（不涉及几何绘制）。

**已核实**（[Esri Japan 官方博客](https://blog.esrij.com/archives/66518)，2025-09）：At 2025-09 仍是 Beta；可执行动作有限，需用 SDK 模板扩展；日文版 3.5 可安装但 **UI 与对话仅英文**；模板通过 Early Adopter Community 的 VSIX 提供。**推断**：ArcGIS Pro 内置助手短期内不会覆盖测绘行业细分工序（如补充耕地验收），这正是本项目自研侧栏的价值区。

**对本项目启示**：① 工具描述/参数描述是模型选对的唯一依据，应写得像"给同事的操作说明"；② 结果应是**结构化回执**而非自由文本；③ 官方把"AI 调用既有公开 API"作为正路——本项目 `MapActions` 正是这个形状，方向正确。

### S2 Knight60/ArcGIS-Pro-MCP（目前最完整的 Pro 侧社区实现）

- **三层回落**：112 个 C# 命名工具 → `run_geoprocessing_tool`（任意 GP）→ `execute_arcpy_code`（任意 arcpy）。**已核实**。
- 桥接：add-in 内 MCP over HTTP `127.0.0.1:6520/mcp`；兼容 TCP 6510；Python 兜底 6511；全部绑定 loopback。**已核实**。
- 性能论证：必须在 Pro 的 Main CIM Thread（`QueuedTask.Run`）上操作 CIM；进程外方案要把活交给 Pro Python 线程再等，约 28 s/次；进程内约 9 ms/次。**已核实**。
- 可视化回读：`export_map_view` 返回 PNG 给 AI"看"；`preview_layout` 渲染到临时图不落盘。**已核实**——这是"AI 自检"的关键设计。
- 确认/撤销：文档把工具按 ⚠ 标注"改/删真实数据"，并建议用户让助手先确认；`save_edits`/`discard_edits` 用于提交/丢弃 Pro 编辑会话（真实撤销通道）。**已核实**；"没有强制逐调用人审"为**推断**（协议层未见 confirm 强制参数）。
- 失败处理：分组错误、`diagnose` 自检、`get_pump_status`；"命令不支持时转 Python 兜底，未启动则报出原因与启动方法"。**已核实**。

### S3 nicogis/MCP-Server-ArcGIS-Pro-AddIn（最小可复制的官方栈拼法）

- 结构：Pro add-in 内 `ProBridgeService` 命名管道服务 + .NET 8 控制台 MCP server（`ModelContextProtocol` NuGet，`WithStdioServerTransport().WithToolsFromAssembly()`）+ `.mcp.json` 给 VS Copilot Agent 模式。**已核实**。
- 工具：`pro.getActiveMapName` / `pro.listLayers` / `pro.countFeatures` / `pro.zoomToLayer` 4 个只读示例；`QueuedTask.Run` 读要素数。无确认、无撤销、无流式。**已核实**。
- 价值：与本项目 `Bridge.cs`（命名管道）+ `mcp_server.py`（MCP stdio）的拓扑几乎同构，可作为"CPython 端用官方 SDK 而不是手搓 JSON-RPC"的对照。

### S4 qiobn/arcpro-mcp

- 桥接：MCP server（独立进程）→ TCP 127.0.0.1:18748 → Pro Python 窗口里的 `arcpro_bridge.py` → `arcpy.mp`；理由是 `ArcGISProject("CURRENT")` 只能在运行中的 Pro 内使用。**已核实**。
- 安全设计：**只读默认**；`execute_python` 双重开关（客户端环境 + Pro 环境 `ARCPRO_MCP_ALLOW_EXEC=1`）；只读工具带 `readOnlyHint`；**每次调用写审计日志** `~/.arcpro_mcp/audit.log`；写入工具"requires confirmation via MCP elicitation"。**已核实表述**，但 Roadmap 同时把"write tools with HITL confirm"列为未完成 v0.2 → **状态冲突，未证实已落地**。
- 体验：结构化输出、MCP resources、图层名自动补全。**已核实**。
- 对本项目启示：**审计日志 + 只读默认 + 双重开关**是低成本高收益组合；本项目已有账本与 `readOnlyHint`，可再补"只读模式"总开关。

### S5 geo2004/MCP-ArcGISPro

- 纯 Python，无需 C#/SDK；Pro Python 窗口执行 `pro_bridge.py`，或用 `MCP_Bridge.pyt` 工具箱按钮启动；IPC 目录 `~/.arcgis_mcp`。**已核实**。
- 硬化层：`run_geoprocessing` **限定工具箱前缀 allowlist**（analysis./management./conversion./cartography./sa./ddd./stats. 等）；`safe_mode`；硬化层加载失败则桥**不启动**（fail-closed）。**已核实**。
- 能力：图层/字段/要素查询、投影、选择、布局与导出（PDF/PNG/JPG/TIF/SVG/EPS）、批量改属性、发布服务、一键"配方"（QC 报告、属性导 CSV、批量出图）。**已核实**。
- 对本项目启示：与本项目 `run_geoprocessing` 的 GP 白名单（8 个工具枚举）同思路；"配方（recipe）"可作为"领域一键任务"的形态参考。

### S6 jjsantos01/qgis_mcp（BlenderMCP 派生）

- 两件套：QGIS 插件内 socket server + 外部 MCP server；明确"strongly based on BlenderMCP"。**已核实**。
- 15 个工具：project/layer/`execute_processing`/`render_map`/`execute_code`；README 对 `execute_code` 有明确风险警示。**已核实**。
- 无确认、无撤销、无进度；渲染出图后不把图回传给模型（工具只给文件路径）。**已核实**（工具签名 `render_map` 返回文件）。
- 对本项目启示：最简单的形态也够用，但**没有回读就没有自检**，AI 会"盲改"。

### S7 nkarasiak/qgis-mcp（工具面与安全设计最完整）

- **125 个工具**（或 `QGIS_MCP_TOOL_MODE=compound` 压到 27 个复合工具，用 `action` + `params`），覆盖要素编辑、字段、样式、布局/图册、SQL、跨图层、插件开发。**已核实**。
- 撤销/事务：`start_editing`/`commit_edits`/`rollback_edits`/`undo_edits`/`redo_edits`，外加 **`create_checkpoint`/`list_checkpoints`/`restore_checkpoint`/`export_session`**。**已核实**。
- 确认：所有工具带人类可读标题与 `readOnly`/`destructive`/`idempotent` 标注；破坏性工具默认**依赖客户端**的确认门；设 `QGIS_MCP_AUTO_CONFIRM=0` 可让服务端再发一次 MCP elicitation。**已核实**。
- 进度：长任务通过 **MCP logging** 上报进度。**已核实**。
- 其他：可选 TCP 共享密钥 `QGIS_MCP_TOKEN`；多实例寻址；`diagnose` 校验插件与 server 版本匹配。**已核实**。
- 对本项目启示：① `destructive` 标注 + 客户端确认 + 服务端二次确认的三档策略，可直接搬到本项目"MCP 路径写操作"；② **compound tool mode** 是控制 schema token 开销的正解，本项目已有"档位裁剪"（Chat/Sampling/Analysis/All），可再评估复合工具；③ checkpoint 是"AI 操作的会话级撤销"最轻实现。

### S8 GIS Copilot（Penn State，QGIS 插件）

- 已核实（[官方发布页](https://giscience.psu.edu/2025/10/01/gis-copilot-v1-0-released/)）：开源 QGIS 插件，用自然语言对矢量/栅格做空间分析；v1.0 默认 **GPT-5** 且可配置推理等级；**改进 GUI 与实时操作状态更新**；**先生成工作流前做任务分析**；一键查看任务分解、数据概览、工具文档；论文 IJDE 2025（doi:10.1080/17538947.2025.2497489）。
- **未证实**：确认/撤销、失败回滚、是否真正执行 GIS 操作还是仅生成模型工作流。
- 对本项目启示："**任务分析 → 工作流 → 执行**"三段式，与"建议卡"是同一件事的两种叫法；"一键看工具文档"说明**专家用户需要可审计的中间产物**，不能只给结果。

### S9 ahujasid/blender-mcp（tool-use 循环的经典范式）

- 9 个工具，核心是 `execute_blender_code`（AI 直接写 Python）+ `get_scene_info`（精简场景摘要，按需下钻）+ **`look`**（viewport/camera/angles 多视角、frames 动画条，solid/material/rendered/wireframe/xray 多种画法）+ 资产/模型生成。**已核实**。
- `look` 的意义：**AI 每次改完能自己看一眼**，形成"改 → 看 → 再改"的闭环；README 明确"so the AI checks its own work"。**已核实**。
- `BLENDER_MCP_SAFE_MODE=1`：执行前静态校验脚本，拦截文件读写、起进程、网络、常驻代码；被拦脚本连同原因回传给 AI 修正。**已核实**。
- 对本项目启示：静态校验 + 结构化场景摘要 + 截图回读，三件套正好对应"失败处理 / 结果回读 / 视觉自检"。

### S10 本项目（对照基线，详见第 6 节）

一句话：**执行侧与协议侧做得比多数样本扎实，交互侧与可视化回读落后于头部样本，绘图能力基本空白。**

## 4. 桥接形态与取舍

| 形态 | 代表 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| A. 进程内 C# add-in | S1/S2/S3/本项目 | 可用 `QueuedTask.Run` 碰 Main CIM Thread，毫秒级；可访问 Layout/符号/相机全 API；可进程内确认弹窗 | 需编译签名、随 Pro 版本重建；调试成本高；第三方调用需自建 IPC/MCP | 需要真实控件、低延迟、原生撤销 |
| B. Pro Python 窗口桥 | S4/S5 | 零编译、改一行即生效；arcpy 全量可用 | `arcpy.mp` 在 UI 线程外受限，延迟高（~28 s/次，S2 实测）；窗口一关即断 | 原型验证、一次性脚本化任务 |
| C. QGIS/Blender 插件 socket | S6/S7/S9 | 插件与外部 MCP 解耦，语言无关；生态成熟 | 需自造协议、超时与 framing；越权风险由 socket 暴露面决定 | 多客户端共享同一桌面应用 |
| D. 一方 SDK 扩展点 | S1 | 模型调用、UI、权限、门户身份由产品托管；扩展只写业务函数 | 受产品版本/组织策略/网络（门户鉴权）限制；扩展粒度由产品定义 | 希望"开箱即用"的通用操作 |

**取舍结论（推断）**：本项目已选 A 且配套命名管道 + MCP server，是正确组合；不要再加第三种桥（现已存在 `arcgis-pro-live` 第二根管道，应合并或明确分工），否则维护面继续膨胀。

**八条可复用契约**

1. **单一真源目录**：侧栏与 MCP 共用同一份工具 schema，启动即校验完整性，拒绝"半可用目录"。
2. **标注即权限**：`readOnlyHint`/`destructiveHint` 不只是说明，要驱动 UI 图标、确认策略与并发闸。
3. **确认双通道**：参数级 `confirm=true` 防模型"顺手做"；人类级确认防模型"自授权"。缺一不可。
4. **读写分离**：只读可并发等待，写入走单一闸；工程/地图身份变化立即取消在途请求（本项目已做）。
5. **长任务必任务化**：有 `job_id`、状态、取消、耗时、输出路径，AI 才能"提交—查询—加载"而不是阻塞。
6. **结果必须可回读**：文字摘要 + 对象引用（图层 URI/要素 OID/文件路径）+ 可选图像；模型看不见就没法自检。
7. **幂等与不覆盖**：导出禁止覆盖、重复加载返回已有图层、重复调用返回同一结果。
8. **审计账本**：每次 AI 运行留一条可检索记录（谁、什么档位、调了哪些工具、失败几次、token 用量、结束原因）。

## 8. 按优先级排序的落地建议

> 每条给：动作 / 理由 / 收益 / 成本 / 风险 / 验收。成本按"人日"粗估，仅作排序参考。

### P0（本轮迭代应做）

**P0-1 写操作"建议卡 + 人审"重构（含 MCP 路径）**
- 动作：把所有非只读工具在侧栏渲染为**内联建议卡**（中文动作名、目标对象、参数表、影响面、是否可撤销、风险级别），卡片内有"执行/调整/取消"；外部 MCP 路径改为**两段式**（`prepare_*` 返回 `preview_token` + 影响面 → `apply_*` 必带 token 且要求 elicitation/人工确认）或直接接 MCP elicitation。
- 理由：G5+G9 是"AI 控制绘图"的信任前提；S7 已证明三档确认可行。
- 收益：误操作率显著下降；参数错误在确认前暴露；MCP 路径不再自授权。成本：中（3–5 人日）。风险：**交互变慢**，可用"本会话信任某工具/只读模式"折中；两段式需令牌过期与一次性语义，否则被重放。
- 验收：对 `remove_layer`/`save_project`/`run_geoprocessing` 在侧栏与 MCP 两条路径各做一次"拒绝执行"演练，均无副作用；账本记录 `status=skipped`。

**P0-2 视觉回读闭环（复用已有 `ReviewMapAsync`）**
- 动作：`export_map`/`export_layout` 增加可选 `return_image`（返回缩略图给模型）；新增 `review_map_preview`（临时渲染不落盘 + 结构化评语）；工具卡内嵌缩略图。
- 理由：G4；S2 `export_map_view`、S9 `look` 都证明"看得见"直接提升自纠率。
- 收益：出图/符号/图例类任务一次成功率提升；用户可与模型看同一张图。成本：低（1–2 人日，代码已存在）。风险：图像上行 token 成本与隐私（外发影像需项目已有告知文案）；须限制尺寸与 DPI。
- 验收：一次"改符号→看结果→再改"的会话中，模型在第二轮引用图像内容（如"图例遮挡右下角"），且图像哈希与导出文件一致。

**P0-3 图斑编辑接入 AI（三个工具，复用 manifest/token）**
- 动作：新增 `preview_parcel_edit`（operation=split/merge，参数含 layer/选中 OID/分割线 WKT 或由人画）、`apply_parcel_edit`（token+operator，必须人确认）、`undo_parcel_edit`；AI 只生成**候选**，候选图层与面积变化由现有 `ParcelEditingPanel` 机制展示，确认仍由人点击。
- 理由：G1+G2；这是本项目唯一"已安全实现但 AI 用不上"的几何能力，也是测绘行业最真实的绘图需求。
- 收益：AI 可完成"按线分割/相邻合并"的候选生成，人工只做核对；风险最低（后端已有摘要校验/状态机/失效规则）。成本：中高（4–6 人日，含画线几何获取与 GP 参数封装）。风险：分割线几何来源（模型生成 vs 人工画）必须二选一明确；模型生成的线**不得**直接落盘，只能进候选。
- 验收：AI 发起一次分割候选后，账本与 manifest 可追溯；取消/撤销后源数据摘要不变（用 `_digest` 对比）。

**P0-4 工具卡结构化与中文语义化**
- 动作：从 `tools.json` 生成卡头（`title` + 中文动作名 + 目标）；参数渲染为键值表（值超长截断、可展开原始 JSON）；结果渲染为**摘要区**（要素数/图层名/路径/耗时）+ 原始 JSON 折叠；同名多次调用**逐次成卡**（用 call id 而非 name 做 key）。
- 理由：G7；这是 UI 改版的地基，成本极低。收益：可读性、可审计性、可教学性。成本：低（1–2 人日）。风险：卡片过多需折叠策略（默认折叠已完成卡）。
- 验收：一次 6 次工具调用的会话中，6 张卡各自可区分、可折叠、可复制参数。

### P1（下一迭代）

**P1-1 撤销栈与"撤销上一步"**：为 AI 写操作记录 undo 描述（图层可见性/符号/顺序快照、导出路径、图斑编辑 manifest），UI 提供"撤销上一步"和"回滚到此处"；不可逆操作（删图层、保存工程）标红并二次确认。成本中高（4–6 人日），风险中（并非所有操作可逆，需在卡上明确标注"不可撤销"）。验收：改符号→撤销，图层符号与顺序复原且账本留痕。

**P1-2 正文流式渲染**：`onDelta` 直接追加到当前助手消息气泡（纯文本 + 轻量 Markdown），停止后保留已生成内容并标注"已停止"；工具卡在流中即时插入。成本低（1 人日）。风险低。

**P1-3 dry-run / 计划预览**：新增 `plan_*` 或 `dry_run=true` 语义（只做校验、路径存在性、要素计数、坐标系统一致性检查，不写盘）；UI 用"计划卡"列出步骤与预计输出。参考 S8 的"任务分析先行"。成本中（3–4 人日）。风险：dry-run 与真跑的判定逻辑必须同源，否则会给出错误信心。

**P1-4 统一双桥**：把 `arcgis-pro-live` 的 4 个动作并入 `tools.json`（context/project），或明确"live 管道仅供采样助手内部使用、不对外"。收益：MCP 侧能力完整、减少一套协议。成本中（2–3 人日）。风险：采样助手是生产路径，改动要灰度。

**P1-5 只读模式与令牌**：设置里加"本次会话只读"总开关（拒绝所有非 `readOnlyHint` 工具）；MCP stdio 支持可选 `PRO_AI_BRIDGE_TOKEN`；HTTP 形态（若上）必须带 token。成本低（1 人日）。风险低。

### P2（后续）

- **P2-1 复合工具模式**（S7）：把"图层类/选择类/分析类"压成 `action+params` 复合工具，降低 schema token；本项目已有档位裁剪，可作为对照组实测再定。
- **P2-2 进度推送替代轮询**：GP 任务与长工具用事件/回调推送到 UI（本项目 `WorkbenchJobService.Changed` 已有事件雏形）。
- **P2-3 一键注册外部客户端**（S2）：写 `.mcp.json`/`claude mcp add` 等价配置，备份原文件，UI 显示"将写入哪个文件"。
- **P2-4 领域建议卡**：把"补充耕地验收"的高频链路（导入→编号→布点→DEM→出图→交付自检）做成可点的建议卡，参数用表单收集，底层调用现有工具组合。
- **P2-5 变更报告**：一次会话结束生成"改动清单"（改了哪些图层/符号/文件/任务），可导出供项目归档——直接复用账本。

## 9. UI 改版专节：专业桌面软件里 AI 侧栏的交互与视觉模式

> 目标：把现有 ChatPane（WPF 代码构建，`ChatPane.cs:82` 起）从"聊天 + 折叠配置"升级为"可读、可审、可回滚的作业面板"，同时保持 ArcGIS Pro DockPane 的空间约束（窄、可停靠、深浅色主题）。

要点：
- **状态条常驻但单行**：用户随时知道"AI 在操作哪个工程/地图/选择集"。本项目已有 `_projectLabel`（`ChatPane.cs:61`、`:537-538`），建议从两行文本改为单行 + tooltip 明细。

- **设置类面板收进"⋯"菜单/独立设置页**：当前"模型设置 + 底图设置"两个 Expander 常驻（`:49`、`:42`、`:121`）会挤压窄栏；建议首启展开、之后收进设置页。

### 9.2 消息与流式

- 用户消息：右对齐或带"你"标签，保留原文；超长折叠。
- 助手消息：**增量渲染**（先出文字再出卡），末尾显示"第 n/N 轮 · 已用 x s"；停止后保留内容并标"已停止（已完成的操作保留）"——与本项目现有 `_status` 文案（`ChatPane.cs:447`）语义一致。
- 流式期间：输入框**不禁用**（现在 `SetBusy` 会禁用设置但保留输入，`:213-220`），允许"排队下一条"；提供"停止请求"（Esc）。
- 禁止：把工具调用过程混进正文；工具卡单独成块，正文只说人话结论。

### 9.3 工具调用卡片（核心组件）

三行结构 + 三态：

| 区 | 内容 | 说明 |
|---|---|---|
| 标题行 | 状态点 + **中文动作名** + 目标对象 + 耗时 + 折叠箭头 | 例：`● 设置符号 · 验收图斑 · 0.8s`；右侧可放"⋯"（复制调用、查看原始 JSON、重试） |
| 参数区 | 键值表（中文键名 + 值 + 单位）；超过 5 行折叠；未知键标黄 | 由 JSON Schema 自动生成，见 9.4 |
| 结果区 | 结构化摘要（数量/路径/图层/状态）+ 原始 JSON 折叠 + 动作按钮（定位图层/打开文件/加载结果） | 摘要文案模板化，避免裸露 JSON |

状态色（同时用**图标 + 文字**，不只靠颜色）：
- 待确认：琥珀色左边条 + "待确认"
- 执行中：蓝色 + 旋转/脉冲 + 已耗时
- 完成：绿色 + "已完成"
- 跳过：灰色 + "已跳过（用户取消）"
- 失败：红色 + "失败" + 一句话原因 + "复制诊断"
- 停止：灰色 + "已停止（不回滚）"

工程细节：**用 call_id 而非工具名做卡片 key**——现在 `_toolCards` 以 name 为 key（`ChatPane.cs:38`、`:260-272`），同名工具第二次调用会覆盖第一次的卡片，这是必须改的。

### 9.4 参数表单（由 schema 自动生成）

- `enum` → 下拉（选项做中文映射，原文放括号）；`boolean` → 开关；`integer/number` → 数字框 + 范围提示 + 单位后缀；`string` 且含 `pattern` → 提示格式示例；`layer` 类参数 → 从当前地图图层下拉（带类型图标与要素数），不要让人手打 URI。
- **`confirm` 参数不应出现在表单里**：它是"审批开关"，应由 UI 的确认按钮置 true。现在 `enum:[true]` 等于"让模型自己填 true"（`tools.json` 多处），人审必须由 UI 承担。
- 必填/选填分组；默认值来自 schema default（当前 tools.json 无 default，建议补）。
- 参数非法时**就地报错**，不要等到执行。

### 9.5 确认与撤销

- 单步：内联建议卡确认（不要模态 MessageBox；现有 `ConfirmAsync` 用 MessageBox，`ChatPane.cs:502`，会打断阅读且无法展示影响面）。
- 批量：提供"全部执行 / 逐个确认"；同一工具可"本次会话不再询问"（写入设置，可撤销）。
- 不可逆操作：红色风险条 + 需要勾选"我已了解不可撤销"或输入工具名确认。
- 撤销：工具卡右上"撤销"（10 s 内高亮），跨步骤在对话流顶部给"回滚到此处"；不可撤销的操作卡显示"不可撤销"而非隐藏按钮。

### 9.6 空态（首次进入 / 清空后）

三块内容，全部可点击：
1. **能做什么**：领域示例卡（"出验收图册"、"体检图斑编号"、"批量出图"、"加载天地图底图"）——直接映射到已有工具组合，点了就填好输入框。
2. **当前上下文**：工程、地图、选中要素数、图层数、模型是否已配置；未配置时给"去配置"按钮。
3. **快捷入口**：`/sampling` `/analysis` `/map` `/layers`（本项目 `PaneState.Commands`，`PaneState.cs:17`），把斜杠命令做成可点芯片，降低记忆负担。

现状：只有一句 `Append("输入任务开始，或输入 / 查看命令。")`（`ChatPane.cs:193`），可保留为兜底但不应是唯一。

### 9.7 错误态与恢复

| 错误类 | 展示 | 给的动作 |
|---|---|---|
| 模型配置错（URL/Key/模型名） | 卡片：哪一项不合法 + 示例 | 打开设置并聚焦该字段；"测试连接" |
| 桥接未就绪/Pro 重启 | 卡片：桥接状态 + 进程号 | "重新检测"；提示"侧栏需在 Pro 中打开" |
| 模型返回协议错（无 choices/tool_calls 非数组） | 卡片：原始响应摘要折叠 | "换模型/重试一次" |
| 参数校验失败 | 工具卡红色 + 具体字段 | "调整参数"（打开表单） |
| 权限/上下文变化（工程或地图被切换） | 卡片：目标已变化 | "重新列出并选择"（本项目已抛此类错误，`MapActions.cs:51`、`PaneState.cs:49-59`） |
| 超时/取消 | 卡片：已停止，已完成写入保留 | **"查询任务状态"而不是"重试"**（避免重复写入，与 `Bridge.cs:114` 文案一致） |

所有错误卡保留"复制诊断"（含 `diagnostic` 字段，脱敏后）。

### 9.8 进度与长任务

- 模型请求：不要 indeterminate 常驻进度条（现有 `_progress`，`ChatPane.cs:48`）；改为消息内"第 2/5 轮 + 已用 8s"。
- GP 任务：阶段名 + 进度条（若 GP 可给）+ 已耗时 + "取消任务"（现有 `_cancelJob`）；完成后卡内直接给"加载结果/打开输出"。
- 轮询改事件推送后（P2-2），任务卡可原地刷新而不用整表重建。

### 9.9 视觉规范（适配 Pro 深/浅色）

- 字体：正文 13 px（Pro 默认 UI 字号），数据/路径/JSON 用等宽 12 px；行高 1.5；中文标点全角。
- 间距：卡片内边距 8–10 px，卡片间距 6 px；段间距 8 px；避免超过 3 层嵌套。
- 颜色：跟随 Pro 主题（浅色 `#F3F3F3` 底 / 深色 `#2B2B2B` 底）；状态色只用于**左边条 3 px + 图标**，不做大面积填充；正文对比度 ≥ 4.5:1。
- 圆角 4–6 px；1 px 边框；阴影仅用于浮层（建议卡、菜单）。
- 图标：优先用 Pro 内置 glyph（图层、选择、任务、警告），避免引入外部图标字体。
- 密度：侧栏窄，**一屏信息量优先于装饰**；工具卡默认折叠已完成项，只展开"待确认/失败/当前执行"。

### 9.10 中文文案速查

| 场景 | 建议文案 |
|---|---|
| 动作名 | 动词+宾语："添加图层""设置符号""导出图册""分割图斑"（不裸露 `set_simple_symbology`） |
| 待确认 | "将要执行：导出图册 → A3、300dpi、42 块图斑；写入新文件，不覆盖。执行？" |
| 执行中 | "正在执行 · 已 3s（可取消）" |
| 完成 | "已完成：1 个图层、42 块（0.8s）" |
| 跳过 | "已跳过：你取消了本次操作，地图未改变。" |
| 失败 | "失败：图层名不存在。可选图层：验收图斑、采样点。 [选择图层]" |
| 停止 | "已停止请求。已完成的操作仍保留；正在运行的地理处理请在任务区取消。" |
| 空态 | "可以这样开始：出验收图册 · 体检图斑 · 批量出图 · 加载天地图底图" |

### 9.11 可访问性与键盘

- 保留并扩展 `AutomationProperties.Name`（现有 `ChatPane.cs:113-114`、`:133-136`），为卡片、状态点、建议卡补名称与 `AutomationProperties.HelpText`。
- 键盘：Enter 发送、Shift+Enter 换行、Esc 停止、↑ 历史（已实现）、`Ctrl+Z` 撤销上一步、`Ctrl+K` 命令面板、Tab 在建议卡按钮间移动；焦点可见环不得被卡片样式吃掉。
- 纯键盘可完成"确认/取消/撤销"三件事，无需鼠标。
