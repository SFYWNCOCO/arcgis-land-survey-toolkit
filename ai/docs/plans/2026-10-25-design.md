# ArcGIS Pro AI Bridge 设计与实施计划

**Goal:** 将 arcmap-mcp 的实时 GIS 控制方式迁移为独立 ArcGIS Pro 插件，提供通用 MCP 与 Pro 内的可配置模型聊天。

**Architecture:** C# Pro SDK 插件是唯一地图执行层，当前用户专用命名管道连接外部 Python MCP。JSON 工具目录同时被 MCP 和聊天代理读取；聊天通过 OpenAI 兼容 Chat Completions 接口调用工具。模型配置保存在本机，密钥使用 Windows DPAPI 保护。

**Tech Stack:** ArcGIS Pro 3.1 SDK / .NET 6 / WPF / Python 3.10+ / MCP Python SDK 1.x。

用户于 2026-10-25 批准独立插件、通用 MCP、模型 API 配置及自主开发测试。独立目录避免与共享工作区现有采样助手的未提交改动混合；原有插件不修改。

## 范围与顺序

1. 创建共享工具目录、管道客户端和 MCP 服务。先编写参数边界、离线工具发现、错误返回及协议集成测试，观察失败，再实现。
2. 创建 C# 参数校验、命名管道服务、地图执行器与模型循环。先用不依赖 Pro 的控制台测试入口检验真实 HTTP 工具调用、确认、取消和轮次上限，再接入 Pro API。
3. 创建中文聊天侧栏、模型设置与密钥保护，支持取消、工具执行记录和高风险操作确认。
4. 构建独立 `.esriAddInX`，校验 DAML 引用、包内目录和内容哈希，生成通用 MCP 配置与便携源码包。
5. 用独立临时测试工程进行真实 Pro smoke：图层清单、查询、显隐、选择、缩放、符号化、导出与地理处理；协议通过、模拟模型通过与真实模型验收分别记录。
6. 按 requesting-code-review 技能交给独立审查者复核，修复重要问题，再发布本地产物和测试收据。

## 主要文件与职责

- `tools.json`：工具名、参数、注释的共同契约。
- `mcp_server.py`：stdio 协议和受限 Windows 管道客户端。
- `addin/ToolProtocol.cs`、`Bridge.cs`：契约验证和当前用户管道服务。
- `addin/MapActions.cs`：唯一地图执行入口；Pro 的 MCT 操作交给 QueuedTask。
- `addin/ModelClient.cs`：兼容 API、有限工具调用循环、取消和响应检查。
- `addin/ChatPane.cs`、`Settings.cs`：中文 UI 和本机加密配置。
- `build.py`、`install.ps1`：构建打包与受控安装。
- `tests/`：Python 协议集成、C# 行为 harness 和真实 Pro smoke。

## 验证与边界

不暴露任意 C#/Python 执行；地理处理首版限明确工具清单。删除图层、保存、导出、GP 需明确确认，输出禁止覆盖。API 只允许 HTTPS，回环地址可用 HTTP 以支持本地模型；拒绝带凭证、query 和 fragment 的 URL。最多 8 轮模型请求；每轮最多 8 次工具调用；错误作为工具结果返回。密钥不进入聊天记录、MCP 或日志。

构建与真实测试隔离：构建过程不替换其他插件；安装仅使用独立 Add-In GUID。Pro 未打开时可以检查 MCP 清单，但地图调用返回可读错误。停止请求不能保证已完成的 GIS 写入回滚，因此输出和返回值必须区分取消与成功。

## 回滚与清理

移除独立 GUID 的 Add-In 目录即可卸载；不删除用户工程、数据或其他客户端配置。临时探针只进仓库 temp/，不清理归属不明文件。交付保留源码、安装包、使用说明、测试报告，排除缓存和临时工程。
